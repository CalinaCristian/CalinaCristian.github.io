# Separate visibility correction — proposal only

Current `weather.js:meteorologicalRange` caps finite reported/preset visibility by cloud/precipitation kind and then by 20 km. Thus the unchanged clear preset's 30,000 m becomes 19,500 m, and a finite overcast report can become 6,000 m solely because the sky is cloudy. This is independent of source-mountain completeness, camera projection and the rejected 00c pictures.

Proposed bounded rule: return an explicit numeric finite positive `visibilityM` unchanged; use the existing kind/cloud/precipitation heuristic only when that field is absent, nonnumeric, zero, negative or nonfinite. Preserve all preset numbers and lighting/particle/snow behavior. Also inspect `render.js:874`, which separately clamps the fog denominator to 150 m: that still overrides a valid sub-150 m report and should use the already validated positive target, with fallback only for an invalid state. Keep the current shared physical-distance/height atmosphere; do not increase values to expose Rainier.

Required controls: every preset unchanged, clear30km and overcast25km preserved, fog220m and a positive50m report preserved, all invalid/missing cases retain finite existing fallbacks, identical weather targets apart from the intentional visibility field, and actual renderer transition/Koschmieder state checks. Native matched source/camera/time/weather images must compare the same finite reported value, including haze/fog, with all main/Ultra passes counted. Mountain disappearance in physically limited visibility does not establish improved mountain quality. No production weather edit belongs to the current regional cache candidate.
