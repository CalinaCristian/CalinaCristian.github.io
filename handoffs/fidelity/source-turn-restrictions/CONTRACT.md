## Source input and identity

- Prefer `data.roadRestrictions:[{sourceId,tags,members}]`, with all raw relation tags and ordered members preserved. `roadRestrictionCoverage` is provenance/scope, not a permission. Merge/dedupe legacy `data.district.sourceReturns.restrictions` by sourceId only; conflicting duplicate bytes become explicit unresolved records.
- Normalize numeric/string references to literal w/n/r IDs without moving or joining geometry. Match an actual directed incoming edge ending at a native node and outgoing edge starting at that same node object; that node’s sourceId must equal the relation’s literal via ID. Edges resolve source identity through access.sourceId (or explicit identical sourceId), including unchanged profile subdivisions. Never use closest ways/angles or native array IDs as an OSM substitute.
- Accept well-formed unconditional node-via restriction relations with exactly one from way, one via node and one to way. Keep missing/duplicate/unrecognized members, conditional restrictions, via-way sequences, unsupported restriction values or ambiguous source identity as named unresolved diagnostics. In particular r21068490’s compiler-only reviewValidation never supplies its absent from member or a universal runtime ban.
- A valid only_ rule whose to-way is absent from the runtime graph still forbids other exits for its actual incoming source. Missing graph incidence is reported separately; it never grants a forbidden shortcut.

## Movement semantics

- Proposed pure API: `buildMotorTurnRestrictions(data,edges)` returns indexed rules plus accepted/unresolved/coverage diagnostics; `motorTurnAllowed(policy,inEdge,inDir,outEdge,outDir,{mode})` consumes no RNG and mutates no data/graph/actor.
- Use raw target-way identity for supported no_left/right/straight and only_left/right/straight relations. Direction is validated at the actual via node; the label is not converted into a guessed geometric angle.
- Same-way no_u_turn/only_u_turn distinguish the immediate reversal of the actual directed incoming leg from its source continuation. Ambiguous same-way non-U-turn relation shapes stay explicit rather than becoming a blanket ban.
- Mode precedence is the most specific applicable restriction key, then motor_vehicle, then unqualified restriction. Except tokens are checked against that explicit actor mode and known ancestors (bus/taxi→psv; passenger-car/taxi→motorcar; motor modes→motor_vehicle/vehicle). Do not infer emergency exemption from a police livery, mass restrictions from visual size, or a delivery exemption without actor state. Preserve unsupported mode/conditional/exception cases in diagnostics. The exact full-catalog tag inventory is being coordinated with Pipera before implementing this part.
- GPS uses the player’s known motorcar mode. NPCs use explicit native bus/trolley/taxi/known passenger categories; any model class without sufficient source-defined mode remains observable rather than silently receiving an invented exception. Rail routing and walking remain separate.

## Consumers

- GPS with applicable motor rules uses incoming-directed-edge A* state: reaching the same node through a forbidden approach cannot suppress a different legal approach. Gate both ordinary expansions and a positive-distance final partial edge. A destination exactly at the via node needs no imaginary outgoing movement. Preserve same-edge direct travel, costs/access/height snapping/source graph and the existing search bound. Data without applicable rules and walking retain the current route algorithm.
- NPC chooseNext and reversal fallback test the same reader alongside existing source access/turn-lane legality. ensureRoute revalidates every future leg with its actual projected incoming edge/direction/lane before motion, preventing an already planned illegal exit from escaping the new check. No graph changes, lane changes, new bypass, U-turn or collision/reset tolerance are introduced.
- Initial-fleet RNG compatibility needs an explicit integration decision. Proposed default: pure rules compile without RNG; constructor/profile fleet generation at native time/frame0 retains its existing random sequence, and each route is validated before the first physical step, where native ensureRoute already runs. There is no temporary permission to take a prohibited turn. This preserves constructor identities/poses while allowing corrected subsequent choices. If policy is required during constructor route generation instead, changed downstream RNG/fleet would need separate explicit acceptance; it will not be hidden as unchanged.
